# 직무용어

## SI (System Integration)
 + `고객사의 요구사항에 맞게 시스템을 새로 구축`해주는 사업
 + 고객이 원하는 시스템을 분석·설계·개발·납품까지 해줌
 + 예시 : 공공기관 민원 시스템 구축, 병원 EMR 시스템 개발
 + 대표 SI 기업 : 삼성SDS, LG CNS, SK C&C 등
 
 + SI 프로젝트 용어
     + **RFP** : Request For Proposal, 발주처가 업체에 제안 요청하는 문서
     + **ISP** : Information Strategy Planning, 정보화 전략 계획
     + **단위 테스트** : 개발자가 기능 하나씩 테스트
     + **통합 테스트** : 전체 시스템 연결해서 테스트
     + **UAT** : User Acceptance Test, 고객이 직접 검수
     + **오픈 컷** : 시스템 오픈 기준일


## SM (System Management)
 + `이미 구축된 시스템을 유지·보수·운영`하는 사업
 + 시스템 오류 수정, 기능 개선, 모니터링
 + 예시 : 공공기관 홈페이지 운영, 은행 시스템 유지보수

 + SM 업무 용어
     + **SLA** : Service Level Agreement, 서비스 품질 보장 계약
     + **티켓** : 처리해야 할 요청/오류 건

---

## 프로젝트 용어
 + **BMT** : Benchmark Test, 제품 성능 비교 테스트
 + **POC** : Proof of Concept, 기술 검증
 + **QA** : Quality Assurnace, 품질 보증
 + **스프린트** : 애자일에서 짧은 개발 주기
 + **백로그** : 해야 할 작업 목록
 + **마일스톤** : 프로젝트의 중요 완료 시점


## 인프라 용어
 + **온프레미스 (On-premise)**
     + 자체 서버 직접 운영
     + 초기 비용 큼
     + 보안 직접 관리
     + 공공기관에서 많이 씀
     + 예시 : 전산실에서 서버 직접 설치

 + **클라우드**
    + AWS/Azure 등 빌려서 사용
    + 초기 비용 적음
    + 유연한 확장
    + 스타트업·IT 기업에서 많이 씀
    + 예시 : AWS EC2, S3

 + **스케일 업** : 서버 성능 높이기 (CPU, RAM 업그레이드)
 + **스케일 아웃** : 서버 수 늘리기 (여러 대로 분산)
 + **로드밸런서** : 여러 서버에 트래픽 분산
 + **리버스 프록시** : 클라이언트 요청을 내부 서버로 전달 (Nginx)

---

## 보안 용어
 + **인증(Authentication)** : 본인 확인
 + **인가(Authorization)** : 권한 확인
 + **SSO** : Single Sign-On, 한 번 로그인으로 여러 서비스 이용
 + **OAuth** : 카카오/구글 로그인 같은 외부 인증 위임
 + **JWT** : Json Web Token, 토큰 기반 인증. 서버 상태 없이 인증 가능
 + **2FA** : Two-Factor Authentication. 2단계 인증 (OTP 등)
 + **RBAC** : Role-Based Access Control, 역할 기반 접근 제어

## 보안 취약점 용어
 + **SQL Injection** : SQL 쿼리에 악의적 코드 삽입 공격, PreparedStatement로 방어
 + **XSS** : Cross-Site Scripting, 악성 스크립트 삽입 공격
 + **CSRF** : Cross-Site Request Forgery, 사용자 권한 도용 공격
 + **HTTPS** : 데이터 암호화 전송으로 중간자 공격 방어
 + **해시** : 비밀번호 저장 시 복호화 불가능한 형태로 변환 (BCrypt)


---
## 네트워크 용어
 + **VPN** : Virtual Private Network, 암호화된 가상 사설망
 + **DMZ** : 내부망과 외부망 사이 완출 구간, 웹서버를 여기에 배치
 + **포트 포워딩** : 특정 포트로 들어온 요청을 서버 내부로 전달
 + **IP 대역** : 192.179.x.x = 사설 IP, 공인 IP = 외부에서 접근 가능
 + **CDN** : Content Delivery Network, 전세계 서버에 캐싱해서 빠르게 전달

## 클라우드/서버 용어
 + **IaaS** : Infrastructure as a Service, 서버/네트워크 제공 (AWS EC2)
 + **PaaS** : Platform as a Service, 개발 플랫폼 제공
 + **SaaS** : Software as a Service, 소프트웨어 제공
 + **컨테이너 (Docker)** : 앱 실행에 필요한 것들을 하나로 묶어서 어디서든 똑같이 실행되게 하는 기술
     + 이미지 (Image) : 컨테이너 실행을 위한 설계도
     + 컨테이너 (Container) : 이미지를 실행한 인스턴스, 이미지 하나로 여러 컨테이너 실행 가능
     + Dockerfile : 이미지 만드는 설정 파일
     + Docker Hub : 이미지 공개 저장소
 + **오케스트레이션 (Kubernetes)** : 컨테이너 자동 배포/관리
     + Docker와 Kubernetes 관계 : 
         + Docker = 컨테이너 하나씩 실행·관리
         + Kubernetes  = 컨테이너 여러 개를 자동으로 관리
         + Docker 없이 K8s 못씀, K8s 없이 Docker 쓸 수 있음

## 개발 직군 용어
 + **PM** : Project Manager, 프로젝트 전체 관리
 + **PL** : Project Leader, 개발팀 리더
 + **AA** : Application Architect, 시스템 아키텍쳐 설계
 + **DA** : Data Architect, DB 설계 담당
 + **DBA** : Database Administrator, DB 운영·관리
 + **QA** : Quality Assurance, 소프트웨어 품질 테스터
 + **DevOps** : 개발(Dev) + 운영(Ops), CI/CD, 인프라 담당

## 기타 용어
 + **레거시** : 오래된 기존 시스템, 유지보수가 어려운 코드
 + **리팩토링** : 기능 변경 없이 코드 구조 개선
 + **기술부채** : 빠른 개발을 위해 미뤄둔 개선 사항
 + **컨플루언스** : 문서 협업 툴
 + **MSA** : Microservice Architecture, 서비스를 작은 단위로 분리
 + **모놀리식** : 하나의 서버에 모든 기능이 있는 구조

---

## 테스트 단계 용어
 + **단위 테스트** : 메서드/함수 하나씩 테스트, JUnit - 개발자 
 + **통합 테스트** : 여러 모듈 연결해서 테스트 - 개발자/QA
 + **시스템 테스트** : 전체 시스템 기능 테스트 - QA
 + **UAT** : 고객이 직접 검수하는 인수 테스트 - 고객
 + **성능 테스트** : 부하 발생시켜서 성능 측정, nGrinder, JMeter - QA/개발자
 + **회귀 테스트** : 수정 후 기존 기능 정상 동작 확인 - QA


## QA/테스트 용어
 + **테스트 케이스** : 테스트할 입력값과 기대 결과를 정의한 문서
 + **TDD** : Test-Driven Development, 테스트 먼저 작성 후 개발
 + **커버리지** : 테스트가 코드를 얼마나 커버하는지 비율
 + **스모크 테스트** : 배포 후 핵심 기능만 빠르게 확인
 + **부하 테스트** : 동시 접속자 늘려서 한계 성능 측정
 + **Mock** : 테스트용 가짜 객체, 실제 DB 없이 테스트 가능
